# Tests and benchmarks

Automated regression suites, reusable test infrastructure, fixture projects, visual baselines and performance scenarios. Verification entry points and PowerShell helpers live in [Scripts/Tests](../Scripts/README.md).

Fixtures intentionally include localized labels, culture-specific output, Unicode/shaping text, invalid source and comment syntax consumed by parser/editor tests. These are test data. Identifiers and test implementation follow the English [repository conventions](../Docs/Repository-Conventions.md).

Linux DRM coverage lives in `Nazor.Linux.Tests`: portable host/surface tests,
native ABI and buffer/failure fixtures, real xkbcommon/input initialization and
CPU fallback into actual Skia rendering. Run [verify-drm.sh](../Scripts/Tests/verify-drm.sh)
on Linux. The separate `DrmHardwareTests` requires explicit local-console opt-in;
see [DRM validation](../Docs/Guide/34-Linux-DRM.md#build-publish-and-verification).

## Shared infrastructure and fixtures

`GallerySampleTests` checks the desktop theme picker, scheme changes, retained control state, forced colors and both scrollbar axes in the Gallery. `ScrollBarTests`, `ScrollBarPlacementTests` and `ScrollBarAnimationTests` cover painted and hit geometry, gutter layout, hover and drag, fades, end-button repetition and capture cancellation. `ScrollbarPropertyTests` covers the NSS declarations. Native visual comparison with the original toolkits is a separate alpha verification step.

`python -B -m unittest discover -s Tests/Verification -p test_gallery_fidelity.py -v` checks metadata rejection, exact PNG decoding, image differences and result de-duplication for the optional Gallery evidence tool. It needs Python 3.

`node --test Tests/Verification/test-capture-leaf-reference.mjs` uses Node 22 or newer to test offline reference preparation, source-selected theme and density controls, and capture output paths. Capturing the actual reference requires the HTML and a browser.

Leaf icon regressions check hollow regions independently of SVG rendering and compare the complete catalog with its source artwork on each native font backend. Failed comparisons write the font and SVG images under the test output's `artifacts/leaf-icons/` directory; the pixel tolerances stay the same across backends.

Visual scenarios must have matching Windows/shared and Linux reference names. `verify-wayland.sh` runs the headless controls and rendering suites before native compositor checks. When a control or theme changes intentionally, review its geometry/style assertions and both native image sets; Windows-only reference updates leave Linux expectations obsolete. Private Fira Sans files keep font selection deterministic, but DirectWrite and FreeType still require separate raster references at the existing tolerances.

The editor build also runs `--roslyn-startup <extension.dll> <IDE directory>` in a fresh process and checks that Roslyn loads without partial-name assembly resolution. The native editing fixtures distinguish the inherited PlainText brace switch from the C# language preference, including explicit C# disabling.

## Run verification

`WindowsBadgeCompositionTests` extends the Windows launcher tests with full mathematical image positioning after fitting, private fonts and missing-glyph fallback, cached native snapshots, asynchronous SVG masks, decorative gradients, independent borders, static transforms and alpha composition at 100%/125%/150%/200%/300%/400% scale. `BadgeStyleTests` covers the 53 NSS longhands, border/background shorthands, cascade order and serialization/code generation. Composed-pixel checks and intercepted shell calls do not establish actual taskbar acceptance; `Native_overlay_accepts_count_icon_and_clear_for_a_real_window` is the separate real-shell probe.

NSS pseudo-element coverage is in `Nazor.Style.Tests/PseudoElementTests.cs` (syntax, specificity, C#/JSON output, scope, variables, viewport/media invalidation), `Nazor.Rendering.Tests/PseudoElementRenderingTests.cs` (generated layout/paint/hit retargeting, 100%/150%/200% scale, Hot Reload, placeholder/IME, aligned and multiline selection), and the NSS language-server/grammar tests (completion, hover, applicability and both IDE classifications). The Theming sample exercises emitted styles with actual field parts. Native IDE and platform acceptance remain separate from these portable/headless checks.

`ControlStateSelectorTests` verifies explicit role/field applicability, effective disabled ancestry, readonly and validation refresh, specificity, generated C# and strict stylesheet JSON. `ControlStateRenderingTests` verifies placeholder-state updates through real composition, cancellation, commit and value replacement. Shared grammar and language-server tests cover the same accepted control-state names and help.

From the repository root with PowerShell 7, Windows x64 and the SDK pinned in [global.json](../global.json):

```powershell
# Build, execute suites and benchmarks, and verify editor artifacts and SDK consumers.
pwsh -NoProfile -File ./Scripts/Tests/verify.ps1

# Run one xUnit v3 executable suite during focused development.
dotnet run --project Tests/Nazor.Core.Tests -c Release
dotnet run --project Tests/Nazor.Application.Tests -c Release

# Check benchmark thresholds and write measured results.
dotnet run --project Tests/Nazor.Benchmarks -c Release -- --check Scripts/Tests/benchmarks.json --out artifacts/benchmarks.json
```

Standard benchmark samples include input and dispatcher processing. A self-check verifies input-time scene updates, queued work and lazy style work before any measured scenario. Wheel scrolling must move on every step; jumps target `ListViewViewport`, must reach each requested endpoint and must keep at most 40 realized rows. `StyleCounterTests` verifies that cumulative style work survives idle updates and counts recomputation even when values stay equal. See the [measurement contract](../Docs/Guide/27-Testing-and-Diagnostics.md#performance-and-hot-reload-tests).

Repository-dependent suites locate the checkout from the source path, working directory or executable directory. When running an assembly built on another OS, an empty directory from the foreign source-path syntax is ignored so the other locations can resolve the checkout.

The Visual Studio checks are separate executables with IDE-specific inputs; [Scripts/Build/build-editors.ps1](../Scripts/Build/build-editors.ps1) orchestrates them. The application test project copies [UiaClient.ps1](../Scripts/Tests/UiaClient.ps1) into its output and runs it through Windows PowerShell 5.1 for cross-process UI Automation.

Native suites can briefly create windows. Desktop pixel tests require an unlocked session with the physical display on; an unlocked session with a powered-off display can return white GPU captures even when the retained framebuffer is correct. Capture per-monitor-DPI window coordinates on its UI thread. `WindowTests.Presented_pixels_match_the_scene` compares actual CPU/GPU presentation with the rendered frame using an interior background sample. Real SendInput and system clipboard tests are opt-in. Rendering baselines should change only after visual review. See the [testing and diagnostics guide](../Docs/Guide/27-Testing-and-Diagnostics.md) for environment switches, baseline updates and manual acceptance boundaries, and the [script reference](../Scripts/README.md) for verification options and workspace behavior.
