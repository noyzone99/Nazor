# Linux desktop bridge ABI

`libnazor-wayland.so` and `libnazor-x11.so` expose ABI version 5 through the shared `nazor-wayland.h` contract. They are independent display modules, without GTK/Qt, a rendering engine or .NET callbacks. The C# adapter selects an instance-specific function table and drains native events on its UI thread. DRM does not load either bridge.

X11 uses Xlib/ICCCM/EWMH, retained XImages, XIM and clipboard selections including INCR. X11 EGL surfaces use XIDs; Wayland EGL surfaces retain their `wl_egl_window` adapter. The X11 module uses ELF NODELETE because Xlib retains a process-wide native error-handler address. All displays, windows, buffers and descriptors are still released; keeping the module mapped avoids dangling callbacks when platforms are created and disposed repeatedly. The buffer/dispatch details below describe Wayland; see [X11](../../../../Docs/Guide/35-Linux-X11.md) for its protocol behavior and limits.

The connection's owning thread handles native objects and callbacks. `nz_wake` may run concurrently while the connection is alive; the managed adapter serializes it against disconnect. The render worker uses borrowed display and surface handles and finishes GPU cleanup before the UI thread destroys the window or releases the connection. For Wayland EGL, the optional `nz_window_wayland_gpu_start` export requests a UI frame on the owning thread. The worker calls `nz_window_wayland_gpu_prepare` before swapping to apply the acknowledged geometry and scale for a matching buffer, and calls `nz_window_wayland_gpu_presented` after a successful swap. The owning thread assigns child windows after that first swap. X11 continues to use `nz_window_gpu_prepare`. A window belongs to exactly one connection. Window destruction invalidates queued events for that window, and disconnect destroys any remaining native objects.

`nz_next_event` returns a copied event structure. Its UTF-8 `text` pointer remains valid until the next call to `nz_next_event` or disconnect. The managed adapter converts it before invoking application code or entering nested dispatch. Errors are stored per connection; `nz_error` is borrowed until the next error/disconnect. No native pointer may be retained after its owning connection is released.

Frame appearance and outer resize use optional ABI 4 exports. `nz_window_outer_resize` creates an input ring measured in logical units, with zero removing the ring. Pointer events from the ring carry `NZ_POINTER_FRAME_OUTSET` and are already translated to the main surface's logical coordinates. Wayland uses an input-only region on a transparent subsurface and sends the triggering button serial back through `nz_window_wayland_resize`. Without compositing, X11 uses a Shape input region on an `InputOnly` companion. With an ARGB visual and a compositing manager, X11 instead adds transparent padding to its managed top-level. Its rendering child remains inside that same compositor surface; `_NET_WM_MOVERESIZE` therefore targets the surface receiving the initiating press under Xwayland. The bridge translates input and configure sizes back to client coordinates and reports `_GTK_FRAME_EXTENTS` in physical pixels. Shape clipping applies to the content and includes the outer band on the parent. The X11 Shape extension also removes input from the separate ARGB shadow window. Both bridges detach auxiliary surfaces when the owner is hidden or destroyed.

The optional X11 export `nz_window_render_surface` returns the borrowed rendering child's XID, or the top-level XID without compositing. EGL uses this XID with `nz_window_native_visual`; `nz_window_native_surface` continues to return the stable managed top-level for ownership and desktop integration. CPU buffers and EGL framebuffers retain client dimensions without the outer padding. Render-child lifetime matches its native owner. Changing the outset preserves the content size; non-normal states remove padding and restore its prior geometry on returning to normal. Window-manager placement policy still applies, including Weston XWM ignoring explicit configure positions.

`nz_window_acquire` returns 1 with a writable shared-memory buffer, 0 while configuration or a free buffer is unavailable, and -1 on allocation failure. Present an acquired buffer exactly once, or release an unused acquisition with `nz_window_discard_buffer`. Presentation transfers write access to the compositor until `wl_buffer.release`. At most three buffers are retained per window, and old dimensions are reclaimed only after release. The adapter keeps its own retained CPU painting buffer. When `nz_window_buffer_is_current` confirms that the acquired buffer contains the last presented frame, it copies only clipped damaged rows; other buffers receive a complete copy. `nz_window_present_damage` submits physical damage rectangles, with full damage on first mapping. Client decoration damage is included separately. GPU rendering uses EGL surfaces and does not copy the normal framebuffer into shared memory.

The event loop pairs `wl_display_prepare_read` with either `read_events` or `cancel_read`, flushes requests, handles write backpressure, and polls the display, wake eventfd and clipboard pipes. Clipboard writers are nonblocking; a slow reader must not stop native dispatch. File descriptors are closed by the side that creates or receives ownership of them. The optional Wayland `nz_clipboard_cancel` export closes an outstanding read. `nz_window_wayland_text_context` sets the focused field, content hint, cursor rectangle and surrounding text in one update. IME context and clipboard sizes are bounded at their native boundaries.

The XML definitions are vendored with upstream copyright/license text. `wayland-scanner` generates protocol bindings during the CMake build. No generated bindings are maintained by hand. Core globals are bound at the smaller of the compositor's version, the system client library's interface version, and the version implemented by this bridge. The compositor is capped at version 4 when the build headers lack the version 6 surface callbacks, even if the installed client library supports newer events. The compositor-binding regression in `input-tests.c` should also be run with a newer client library than the build headers.

Build and test through [build-native.sh](../../../../Scripts/Build/build-native.sh) and [verify-wayland.sh](../../../../Scripts/Tests/verify-wayland.sh). The [X11 test harness](x11-test-server.sh) waits for Openbox's post-startup command before launching a client. The [Linux guide](../../../../Docs/Guide/33-Linux-Wayland.md) owns the public feature mapping and interactive verification checklist.

When Xvfb, a Weston version with client launch support, Xwayland and libXtst are available, CMake also registers `xwayland-outer-resize`. Its [nested harness](xwayland-test-server.sh) sends XTest input to an outer Xvfb hosting Weston's X11 backend, so pointer events cross the real Wayland compositor boundary. The test checks transparent pixels, unchanged client dimensions during live outset changes, an actual drag starting beyond the window-manager shadow, and maximize/fullscreen restoration. CMake `XWAYLAND` can select a separate executable. Missing runtime client-launch support skips this optional test with exit 77.

External popups use optional ABI 4 exports `nz_popup_create`, `nz_popup_place`, `nz_popup_work_area` and `nz_popup_input_region`. The managed host enables this path only when all exports are present and transparency is available. Placement and input regions use logical coordinates. Popup geometry excludes the transparent painting margin. Wayland reports configured geometry and dismissal as events 23 and 24, and the compositor controls the final position. X11 uses RandR monitor bounds intersected with the current desktop work area and reports owner movement as event 25. Destroy nested popups before their native parent. Popup buffers use the same acquire/present ownership contract as ordinary windows.

The adapter batches keyboard focus changes across the owner and its popups before reporting family focus loss. X11 also observes `_NET_ACTIVE_WINDOW` on the root and reports activation as event 22, including while a popup has a keyboard grab. Event 25 sets `a` when Button1 is held during owner configuration so an interactive move dismisses transient popups. Popup placement flags use bit 0 for keyboard grab, bit 1 for menu type and bit 2 for outside dismissal. Persistent X11 surfaces acquire no pointer grab, including when restoring capture after a nested surface closes.

Explicit decorations require ABI 5. Bit 0 of `nz_decoration_support` reports native-decoration negotiation (Wayland) or an observable EWMH window manager (X11). Bit 1 identifies a provider that cannot change frame ownership on a mapped window; currently this is Weston XWM. `nz_window_decoration_mode` returns 0 for unknown, 1 for client and 2 for server decorations. Wayland records the compositor's configure result; X11 reads `_NET_FRAME_EXTENTS`, rather than treating a Motif request as acceptance. Weston XWM can retain native extents for a shadow-only wrapper: only for the identified `Weston WM`, a mapped client centered in a symmetric wrapper smaller than every reported extent confirms client ownership. Native geometry and unrecognized window managers retain the ordinary observation path. Geometry changes also notify capability observers. The managed layer owns the exact policy and its authorized fallbacks. A missing native-decoration provider does not authorize a bridge-drawn fallback caption.

X11 outer resize companions support both client-title-bar windows and fully Nazor-owned frames. The internal borderless flag describes frame ownership and does not disable interactive resizing; managed operation settings control whether the companion is requested.

Some window managers omit `_NET_FRAME_EXTENTS` when a window starts with client decorations. In that case, client ownership requires a viewable, border-free client with an ICCCM `WM_STATE` of NormalState and no additional frame geometry anywhere along its ancestor chain to the root. Every intermediate wrapper must have zero client offsets, zero border width and identical dimensions. Traversal is bounded to 32 ancestors; any unobserved, unmapped or larger wrapper keeps ownership unknown. This handles nested KWin-style wrappers without confusing an undecorated inner wrapper with a native outer frame.

Generic capability notifications use zero for the decoration field; they do not acknowledge an ownership request. Positive values come from a Wayland decoration configure. X11 notifies on frame-extents, ICCCM state, mapping and geometry changes; observers query the current ownership independently of the notification payload. X11 has no explicit rejection response: an ownership mismatch remains pending until matching observation or the bounded negotiation timeout. When a native-decoration provider exists, unconfirmed client and server ownership are reported as Unknown.

The optional `nz_window_foreign_parent` export accepts `x11:<hex-XID>` or `wayland:<xdg-foreign-v2-token>` on its matching backend. X11 sets `WM_TRANSIENT_FOR`; Wayland binds the optional importer and retains/releases the imported object with the child. Unsupported compositor protocols return false through the managed `IPlatformWindow.SetOwner` contract. Native ownership does not replace application lifetime tracking.
