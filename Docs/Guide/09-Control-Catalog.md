# Control catalog

The SDK supplies `Nazor.Controls`. Use its application controls for ready-to-use UI and import `Nazor.Controls.Primitives` when composing an interaction. Basic supplies the default styles and focus cues. The optional NazorLeaf theme also provides [theme-specific controls](#optional-theme-controls).

Search this page by Razor tag name. Each tag links to its declarations and member contracts. Example links open the source used by the [runnable Gallery](../../Samples/Nazor.Samples.Gallery/README.md). A single example can illustrate several related controls.

The NumberField example exposes `Compact`, `Inline` and `Hidden` spin-button presentations and an opt-in arithmetic expression checkbox. Fluent Compact uses a focus-triggered anchored flyout; Basic/NazorLeaf use an in-field stack. See [numeric editor usage and migration](10-Text-Input-and-Data-Controls.md#choose-an-editor).

[Text and media](#text-and-media) · [Layout and disclosure](#layout-and-disclosure) · [Commands and selection](#commands-and-selection) · [Forms and editors](#forms-and-editors) · [Collections and navigation](#collections-and-navigation) · [Menus and overlays](#menus-and-overlays) · [Feedback and window frame](#feedback-and-window-frame) · [Reusable primitives](#reusable-primitives) · [Optional theme controls](#optional-theme-controls)

NSS selectors match retained elements, including named parts rendered by controls. For example, `TextField` is the outer control and `TextFieldInput` is its editable part. Name interactive controls with visible text or their accessibility properties. For part names and scope, see the control's API contract, the [selector guide](17-Selectors-and-Media-Queries.md#component-boundaries), and the retained tree in [DevTools](../DevTools.md).

Application controls below are in `Nazor.Controls`. The reusable primitives section covers concrete components in `Nazor.Controls.Primitives`. Base classes, models, events, and enums are in the [package reference](../ApiReferences/Nazor.Controls.md).

`Select` and `ComboBox` share `DropDownPlacement`. `Auto` prefers below and uses the available space above when needed. Use `Top` or `Bottom` to request a position. `PreferredMaxVisibleItems` defaults to 10 and sizes the list in options. `PreferredMinVisibleItems` is an optional placement target. The list fits the available space and scrolls to expose the remaining options.

Counts must be positive and the preferred minimum must be at most the preferred maximum. Disabled options count as rows, while group headings consume space in addition to those rows. Templates can give options different heights. A short filtered result shows its actual options and keeps the resolved side while that side remains usable. The [popup surface setting](11-Commands-Menus-and-Popups.md#popup-surfaces-outside-the-window) determines whether placement measures the window viewport or the display work area.

## Optional theme controls

The `Nazor.Themes.NazorLeaf` package supplies [`LeafMark`](../ApiReferences/Nazor.Themes.NazorLeaf.md#leafmark), [`LeafTitlebar`](../ApiReferences/Nazor.Themes.NazorLeaf.md#leaftitlebar), and [`LeafWindowButtons`](../ApiReferences/Nazor.Themes.NazorLeaf.md#leafwindowbuttons). Use the mark in NazorLeaf-styled content and the title bar and buttons for theme-specific window chrome. The [Gallery application](../../Samples/Nazor.Samples.Gallery/App.nazor) uses the mark and prefers the system's window decorations. `NazorLeafTheme.Theme` statically registers the automatic title-bar and caption-button presenters; explicitly choosing Nazor decorations applies them. `LeafTitlebar` remains a reusable surface presenter.

`NumberPresenter` is a reusable primitive for scene-clock scalar presentation. Its typed child context supplies the displayed value and boundary flags; NSS owns the policy and the application retains its actual accessible value. See [numeric presentation](23-Transitions-and-Animations.md#numeric-presentation) and its [interactive example](../../Samples/Nazor.Samples.Gallery/Examples/Primitives/NumberPresenterSample.nazor).

## Badge indicator content

ChildContent is the decorated control; IndicatorContent is the small status visual. Choose a typed icon to preserve its matching font, and register that icon package's fonts before building the application. The Gallery already registers the optional NazorLeaf font used here:

```nazor
@using Nazor.Themes.NazorLeaf
<Badge Icon="@LeafSymbol.At" AccessibleName="Mentions"><Button>Messages</Button></Badge>
<Badge AccessibleName="Synchronization needs attention">
    <ChildContent><Button>Sync</Button></ChildContent>
    <IndicatorContent><TextBlock>!</TextBlock></IndicatorContent>
</Badge>
```

Precedence is Dot, Count, IndicatorContent, Icon, then Text. A zero Count hides the indicator even if a lower-priority visual is provided, unless ShowZero is true. Icon/custom visuals default to localized new-activity text; supply a meaningful AccessibleName. IndicatorContent is decorative, disabled and hidden from accessibility; interactive content belongs in the decorated target. The indicator exposes one current name, and visual caps do not cap its accessible count. [Count replacement and motion](23-Transitions-and-Animations.md#badge-count-replacement)
