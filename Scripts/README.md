# Repository scripts

Run `bash Scripts/Tests/verify-drm.sh Release` on Linux for DRM single-view
managed/native fixture checks. An optional second argument supplies a prebuilt
`Nazor.Linux.Tests.dll`. Results go under `artifacts/drm-tests`; real display
ownership is never requested by this script. Physical DRM testing is separately
enabled as described in the [DRM guide](../Docs/Guide/34-Linux-DRM.md).

PowerShell entry points for building editor artifacts, packaging Nazor, and validating the repository. Run commands with PowerShell 7 on Windows x64 and the .NET SDK pinned in [global.json](../global.json). The UI Automation helper uses Windows PowerShell 5.1 because it loads the Windows UI Automation assemblies.

## Directory layout

| Directory | Responsibility |
| --- | --- |
| [Build](Build) | Build and inspect editor distribution artifacts. |
| [Packaging](Packaging) | Build NuGet package artifacts from source. |
| [Assets](Assets) | Regenerate checked-in asset catalogs from pinned source data. |
| [Tests](Tests) | Run repository and external-consumer verification; provide benchmark thresholds and the UI Automation test helper. |

All maintained PowerShell scripts live here. Editor runtime code, including the VS Code JavaScript entry point, remains with its project under [Sources/Tools](../Sources/Tools).

## Build and packaging

The [Packages workflow](../.github/workflows/packages.yml) runs on pushes to `main` and `dev` and on demand. It builds and tests the native bridges for the four supported Linux RIDs before packing NuGet packages. Download the `nuget-packages` and `editor-extensions` artifacts from the workflow run for the NuGet and symbol packages, the Visual Studio and VS Code VSIX files, and the TextMate ZIP.

On a new tag push, the workflow uses the same native matrix to build and attach the [portable Gallery](../Samples/Nazor.Samples.Gallery/README.md#package-the-portable-release) to the GitHub Release.

`Tests/verify-gallery-fidelity.py --manifest <input-manifest> --out <directory> --results <xunit-xml...>` records Gallery evidence and reference/font hashes. `--compare <reference-json> <actual-json>` checks lossless PNG captures with zero pixel tolerance and requires complete environment metadata. This optional script uses Python's standard library.

`Tests/capture-leaf-reference.mjs --manifest <input-manifest> --browser <absolute-browser-path> --out artifacts/<fresh-directory>` captures a supplied HTML reference offline with a fresh headless Chromium profile. Node 22 or newer is required. `--validate-only` checks inputs without starting a browser.

`Assets/generate-fluent-symbols.ps1` regenerates the Regular/Filled `FluentSymbol` C# members and their API reference from the checked-in upstream JSON maps. It verifies the TTF/map SHA-256 hashes in `Sources/Themes/Nazor.Themes.Fluent/Catalog/Source.json` before generating. Use `-Check` to verify reproducibility without writing files. Updating the upstream release requires updating the fonts, maps, notices and source manifest together; regeneration does not download assets.

`Assets/generate-nazorleaf-symbols.py` expands the original SVG strokes into OpenType/CFF outlines, generates `NazorLeafIcons.otf` and `LeafSymbol.g.cs`, and updates the API catalog rows. The stable private-use codepoint map lives in `Sources/Themes/Nazor.Themes.NazorLeaf/Catalog/Symbols.json`; add new entries without renumbering existing icons. Install the development-only packages from `Assets/requirements-nazorleaf-icons.txt` in an isolated Python environment. Run `python Scripts/Assets/generate-nazorleaf-symbols.py --check` with that environment to verify deterministic font, C# and documentation output without writing. Application builds use the checked-in font and generated code and need neither Python nor these packages.

`Tests/verify-font-symbols.ps1 -Theme Fluent -Feed <package-directory>` creates isolated .NET 8/9/10 SDK consumers, compiles typed/custom/raw icon markup, checks private-font shaping without system discovery, and runs the built and published outputs. Use `-Theme NazorLeaf` for its corresponding font/catalog package. It compares every deployed font and notice against source files. `-Frameworks net8.0`, `net10.0` or `net11.0` limits the matrix; `-Workspace <directory>` selects the preserved logs/consumer location. The feed must contain the current release's SDK/runtime/theme packages; third-party dependencies are restored from the local NuGet cache.

`Tests/verify-controls-packages.ps1` verifies a fresh NuGet consumer on .NET 8, 9, 10 or 11. It compiles components and NSS with the bundled .NET 10 LTS compiler while preserving the selected application target, renders packaged controls, and checks the dependency graph, the control assembly and the Italian satellite assembly. The generated markup mounts ColorPicker, typed NavigationView/BreadcrumbBar/FlipView, PipsPager, segmented date/time pickers, NumberPresenter and typed/custom Badge indicators in addition to the original fields, tabs and progress controls; every added type must belong to the unified controls assembly. Use `-DeploymentModes trim,aot` for publish checks with the native toolchain installed. `verify-sdk.ps1` includes all four application frameworks.

# Full verification, including SDK checks.

Commands above assume the repository root as the current directory. Scripts resolve repository inputs and default output directories relative to their own location. Relative custom `-Output` and `-Workspace` values refer to the caller's current directory.

SDK and hot-reload workspaces isolate inherited build properties and NuGet configuration. Hot-reload verification restores its temporary process environment on both success and failure, including an initial application build failure.

The editor build script deletes and recreates its output directory. The SDK and hot-reload scripts delete and recreate their workspace on each run, including custom paths. Native tests can briefly create windows; `-RealInput` requires an interactive desktop and temporarily takes foreground. Hot-reload verification creates a window without activating it.

### Bundled DevTools acceptance

`Packaging/pack.ps1` builds the framework-dependent win-x64/linux-x64 inspector payloads while packing Nazor.DevTools.Agent. The Agent's package target also runs when packing the solution directly. Build/copy is gated by NazorEnableDevTools in consumers; the UI stays outside the application dependency graph. Install the .NET 10 runtime for the tool.

- `Tests/verify-devtools-launch.ps1 -Workspace <fresh-absolute-path> [-Framework net8.0] [-Production]`: fresh NuGet consumer with native F12, modifier/repeat exclusion, per-window reuse, owner-bound lifetime, asset diagnostics and production absence. Requires Node and a desktop session.
- `bash Tests/verify-devtools-launch.sh <fresh-absolute-path> [net10.0|net8.0|net9.0|net11.0] [feed] [development|production]`: corresponding native Linux/Wayland check. `NAZOR_TEST_SDK_DRIVER` can explicitly select an installed SDK driver; `NAZOR_TEST_NODE` can select the Node executable. These are test-environment overrides, not application configuration.
- `Tests/verify-devtools-launch.mjs <absolute-apphost> <fresh-absolute-gate> [development|production]`: native lifetime/input driver used by both wrappers. F12 is delivered through the real window-host input callback; physical foreground input remains a separate manual check.
- `Tests/verify-devtools-breakpoints.ps1 -VisualStudio 2022 -FixtureFramework net8.0 -Native` (or 2026/net10.0): dedicated experimental IDE deployment, automatic F12 debugger connection, command reuse, raw fields, UIA at stops and retained data after exit. After an editor version upgrade, refresh only the dedicated profile with devenv /RootSuffix DevToolsDT01 /UpdateConfiguration if its cached registration is stale.
- `Tests/Fixtures/DevToolsVSCode/test.cjs`: real extension-host acceptance, not a mock adapter. NAZOR_DT11_CONFIG points to a JSON object with absolute program/output paths, native:true and optional f12:true. Launch Code with isolated user-data/extensions, the built Nazor extensionDevelopmentPath and this extensionTestsPath. Install Microsoft C# first. f12:true verifies automatic bridge discovery and IDE reuse; Windows also probes actual UIA at every stop and after exit.
- `dotnet run --project Tests/Nazor.Benchmarks -c Release -- --devtools --samples 30 --out artifacts/devtools-benchmarks.json --check Scripts/Tests/devtools-benchmarks.json`: 700-node no-Agent/detached/idle/active/slow-reader cases.
